# QuestLog — Claude Code Context

## Project Overview

QuestLog is a gamified habit tracker PWA built with **Vite + vanilla JS + Supabase**.
Multi-page app (landing, auth, main) deployed to GitHub Pages. No framework — pure JS modules.

## Check Docs First

**Before exploring the codebase, always read `docs/index.md` first.**
It covers the full architecture, key modules, environment variables, SQL migrations,
and the CI/CD table. Reading it avoids redundant raw file searches.

For generated API reference (function signatures, params, return types), check `docs/api/`
(auto-generated by JSDoc — see Documentation System below).

## Documentation System

Two-layer structure:

| Layer | Location | How it stays current |
|-------|----------|----------------------|
| Architecture & dev guide | `docs/index.md` | Manual — update when adding modules or migrations |
| API reference (JSDoc) | `docs/api/` | Auto-generated by `docs.yml` CI on every push to `main` that touches `src/**/*.js` |

**Pipeline**: push to `main` → GitHub Actions runs `npm run docs` (JSDoc) → bot commits
`docs/api/` back with `[skip ci]` to prevent re-trigger loops. `docs/api/` is gitignored
locally; it only lives in the repo via the bot commit.

## Key Source Files

| File | Role |
|------|------|
| `src/lib/utils.js` | Pure utility functions — XP math, level curve, streak multipliers, `escapeHtml`, date helpers. Fully unit-tested (~98% coverage). |
| `src/lib/supabase.js` | Singleton Supabase client. Reads `VITE_SUPABASE_URL` + `VITE_SUPABASE_ANON_KEY` from env — never hardcode credentials. |
| `src/main.js` | App shell entry. Auth init, render pipeline, all feature modules (Task CRUD, Goals, Streak, Leaderboard, Calendar). |
| `src/auth-entry.js` | Auth page entry (excluded from coverage thresholds). |
| `src/landing-entry.js` | Landing page entry (excluded from coverage thresholds). |

## Dev Workflow

- **Feature branches**: use `claude/<description>-<id>` naming
- **CI triggers**: `test.yml` runs on push to `main` or `claude/**` branches, and on PRs to `main`
- **Docs trigger**: `docs.yml` runs only on push to `main` when `src/**/*.js`, `docs/index.md`, or `jsdoc.json` changes
- **Deploy trigger**: `deploy.yml` runs on push to `main`

## Common Commands

```bash
npm run dev          # local dev server at http://localhost:5173/QuestLog/
npm run test:run     # run all tests once
npm run coverage     # run tests with coverage report
npm run docs         # generate docs/api/ locally from JSDoc annotations
npm run build        # production build to dist/
```

## Environment

Copy `.env.example` → `.env.local` and fill in Supabase credentials.
For CI, secrets are set under GitHub → Settings → Secrets → Actions:
`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`.

## Testing

- Framework: Vitest with jsdom environment
- Config: `vitest.config.js`
- Coverage thresholds: 15% globally; `src/lib/utils.js` has per-file rules
- Coverage reports posted as PR comments automatically by `test.yml`
